# openclaw — Source-Level Dossier

Repo: `openclaw/openclaw` — TypeScript, ~392k★, "The AI that really does things. Any OS. Any Platform. The lobster way" (formerly clawdbot/moltbot). Audited from shallow clone of `main`.

Scope audited: `src/entry.ts`, `src/gateway/**` (server, kernel, agent-turn), `src/agents/**` (embedded-agent-runner, tools, subagents), `src/channels/**`, `src/cron/**`, `src/pairing/**`, `src/daemon/**`, `src/state/**`, `src/config/sessions/**`.

## 1. REPO MAP

pnpm monorepo (`pnpm-workspace.yaml`): `src/` (main TS source tree), `apps/`, `packages/` (incl. `packages/gateway-protocol`, `packages/gateway-client` — the shared WS client), `extensions/` (channel plugins), `docs/`, `crates/` (some Rust already), `custodian-skills/`, `skills/`, `deploy/`, `qa/`, `ui/`. Root shims `openclaw.mjs` → `src/entry.ts`.

Entry chain (`src/entry.ts::runEntryMain`): runtime guard → **respawn chain** — `runNodeHostLauncher` (`src/node-host-launcher.mjs`, pins a managed Node), `respawnWithoutOpenClawCompileCacheIfNeeded` (`src/entry.compile-cache.ts`), `buildCliRespawnPlan`/`runCliRespawnPlan` (`src/entry.respawn.ts`) — each stage re-execs a healthier child and the parent exits; the survivor sets `process.title = "openclaw"` and dispatches CLI (`runMainOrRootHelp`). The gateway core lives in `src/gateway/` (server in `server*.ts`, turn pipeline in `gateway/agent-turn/`), the agent runner in `src/agents/embedded-agent-runner/`, sessions in `src/config/sessions/` + `src/sessions/`, persistence in `src/state/` (SQLite: `openclaw-state-db.ts`).

## 2. AGENT LOOP & SESSION

**Turn pipeline (gateway side)** — `src/gateway/agent-turn/agent-turn-service.ts::createAgentTurnService().startTurn`: a strictly phased coroutine: cached replay (`replayAgentTurnIfCached`, `agent-dedupe.ts`) → `prepareAgentRequestRouting` → `acquireSessionActorStorage` (per-session storage lease with `assertCurrent`/`assertReadable`/`authorize` closures) → `prepareAgentContentPhase` (media offload → `OffloadedRef`) → `createAgentAdmissionController` → `runAgentResetPhase` (`/new|/reset` per `gateway/agent-command-policy.ts::AGENT_SESSION_RESET_COMMAND_RE`) → `prepareAgentSession` → `startAgentRunExecution` (`agent-run-execution-phase.ts`) → `persistAgentSessionPhase` → `resolveAgentDeliveryPhase` → `prepareAgentWaitForTurn`. Every phase re-asserts admission currency through **composed assertion closures**: `composeSessionSourceAssertion([assertContextCurrent, assertAdmissionCurrent, assertInputCommitAllowed])` — invalidation-safe callbacks that each carry their own "am I still the live request?" check.

**Runner (agent side)** — `src/agents/embedded-agent-runner/run-orchestrator.ts::runEmbeddedAgent`: `prepareEmbeddedRunSession` → `withRequiredSessionPlacement` → `runEmbeddedAgentForSession`, which builds `createEmbeddedRunLaneController` exposing `enqueueGlobal` / `enqueueSession` — a **two-level run queue**: a per-session lane (serializes turns on one conversation) inside a global lane (bounds total concurrency), with `noteLaneTaskProgress` and `setLaneTaskDeadline` used for watchdogs. Before enqueueing it awaits `waitForSessionMaintenance` + `waitForSessionTranscriptProjection` so compaction/transcript rebuilds never race a new turn. Dispatch may hand off to an external CLI backend (`runEmbeddedAgentViaCliBackendIfEligible`), otherwise acquires a **prepared-model-runtime lease** (`acquireAgentRunPreparedModelRuntime`, with an isolated read-only variant for probes) that pins config/plugins/model for the whole run; a mismatch throws `PreparedModelRuntimeInitialRunAdmissionError` and the orchestrator retries the next candidate. Compaction machinery lives in `run/compact*.ts` (`compactEmbeddedAgentSession`, successors in `run/compaction-successor.ts`).

## 3. GATEWAY / ALWAYS-ON ARCHITECTURE

`src/gateway/server.ts::startGatewayServer` (default **port 18789**) is the canonical start: installs the DB engine role, `acquireGatewayLock` (`src/infra/gateway-lock.ts`, single-owner file lock with `GatewayLockIdentity`, `GatewayLockError`, 5-min lifecycle timeout) → `captureGatewayStateOwner` abort signal so a lost lock shuts the server down. On Linux it optionally wraps everything in a **spawn broker** (`src/process/spawn-broker/context.ts::startGatewaySpawnBroker`) — a brokered process-spawner that survives vfork/page-table costs and restarts itself.

`server-kernel.ts::createGatewayKernel` builds the kernel without sockets: `GatewayScheduler` (`src/infra/gateway-scheduler.ts`), plugin metadata lifecycle, `bootId` (UUID, 1–96 chars), then `prepareGatewayKernelState` → `prepareGatewayLifecycle` → `startGatewayCoreRuntime` → `prepareGatewayKernelRequestRuntime`. Transport is in `server-runtime-state.ts::createGatewayHttpTransport`: node `http.Server` + `WebSocketServer` (from `packages/gateway-client/src/websocket.js`), `attachGatewayUpgradeHandler`, per-message deflate, optional TLS, **Tailscale ingress**, a `PreauthConnectionBudget` (pre-auth connection limits), auth rate limiters (`auth-rate-limit.ts::createGatewayAuthRateLimiter`), and lazy plugin HTTP/upgrade handlers loaded only when a route matches. The Control UI (web client) and OpenAI-compatible chat-completions endpoints hang off the same server. Daemons: `src/daemon/` installs the gateway as **launchd / systemd / schtasks** services (`launchd-*.ts`, `systemd-*.ts`, `schtasks-*.ts`) with restart-storm guards (`restart-storm.ts`). Pairing: `src/pairing/pairing-store.ts` (SQLite store; `upsertChannelPairingRequest`, `approveChannelPairingCode`), `setup-code.ts`, `pairing-challenge.ts` — clients/DM senders pair via codes before being trusted.

## 4. CHANNELS & ROUTING

Channels are **plugins**, not core: `src/channels/registry.ts` (`listRegisteredChannelPluginIds`, `ChannelMeta`, `formatChannelSelectionLine`), plugin contracts under `src/channels/plugins/` (e.g. `ChannelApprovalNativeAdapter` for native approval surfaces, `ChannelAccountMutationPlugin`). Inbound path: `channels/inbound-event/` → `inbound-debounce-policy.ts` (debounce bursts into one turn) → `mention-gating.ts` / `command-gating.ts` (group vs DM rules) → `allow-from.ts` + `allowlist-match.ts` (sender allowlists) → `session-envelope.ts` wraps channel+chat+thread identity → `src/routing/` resolves account/session targets (`resolveChannelAccountKey`, session keys per `src/sessions/session-id.ts`, `agent-harness-session-key.ts`). Threading: `thread-bindings-*.ts` bind channel threads to session IDs so replies route back. Outbound: `run-state-machine.ts` + `streaming.ts` + `progress-draft-compositor.ts` compose live "draft" updates (typers, edits, reactions via `status-reactions.ts`) with channel-appropriate formatting (`isMarkdownCapableMessageChannel` in the orchestrator picks markdown vs plain tool results).

## 5. TOOLS & SECURITY MODEL

The single most security-relevant file is `src/agents/agent-tools.ts::assembleOpenClawCodingTools` — a **generator** that yields plugin-tool batches mid-construction and finally returns the assembled tool list. Key layers:

- **Policy resolution**: `prepareCoreToolPolicy`, capability profile `resolveConversationCapabilityProfile` (per-conversation allow/deny lists, `explicitToolOverrideAllowlist`, requester vs execution agent split: "Tool restrictions can belong to another agent. Never use that owner for credentials").
- **Exec approval**: `src/agents/agent-tools.before-tool-call.approval.ts` — `resolveBeforeToolCallApprovalOutcome`, `requestDeferredPluginToolApproval`/`cancelDeferredPluginToolApproval`; policy in `agent-tools.before-tool-call.policy.ts`; run-level wait in `src/agents/agent-run-approval-wait.ts`; approvals are routable to a trusted device/channel via `src/gateway/approval-channel-custody.ts`, `approval-session-audience.ts`, `approval-web-push.ts`.
- **Exec config**: `resolveExecToolConfig` (`agents/lazy-exec-tool.ts`) merged through `projectEffectiveExecPolicy` (`agents/session-permission-exec-mode.ts`) — supports `safeBins` + `safeBinTrustedDirs` + `safeBinProfiles` (allowlisted binaries that skip prompting), `strictInlineEval`, `reviewer` (an LLM exec reviewer with transcript), background/timeout budgets.
- **Sandbox**: `options.sandbox` carries `workspaceDir`, `fsBridge` (FS calls proxied into the sandbox), `workspaceAccess: "ro"`, browser bridge; `containmentRoot`/`codingRoot` feed FS policy (`workspaceOnly`, `readOnlyRoots` for subagent attachments).
- **Process hygiene**: `resolveProcessToolScopeKey` scopes every spawned process to the session; one-shot runs register cleanup (`supervisor.acquireScopeCleanup(scopeKey, { processTree: "owned-only" })` + `waitForExecScope` from `bash-process-registry.ts`).
- **Memory-write provenance**: `createMemoryWriteProvenanceObserver` tags each workspace mutation `agent` vs `untrusted` (based on `senderIsOwner`/turn-taint) — a tamper-evident record of who caused each write.

## 6. AUTONOMY SCAFFOLDING

`src/cron/` is a full scheduler subsystem: `CronService` (`service.ts`) with `wake()`, arm/timer tests, SQLite-backed store (`store/`, with read-only worker fallbacks), delivery planning (`delivery-plan.ts`, `delivery-preview.ts`), run history/recovery (`run-history.ts`, `service.restart-catchup`), pacing/stagger (`pacing.ts`, `stagger.ts`), and **system-owned declarations** (`system-owned-declaration.ts`): heartbeat is modeled as a cron job — `heartbeat-task.ts::heartbeatTaskDeclarationKey` (`HEARTBEAT_TASK_DECLARATION_PREFIX${agentId}:...`), `heartbeat-monitor.ts` (`DEFAULT_HEARTBEAT_EVERY` from `src/auto-reply/heartbeat.ts`), so proactive "heartbeat" turns are just scheduled jobs that cannot be deleted by the agent (plus `cron-tool-creator-cap.ts` capping agent-created jobs). Isolated runs: `cron/isolated-agent.ts` provisions fresh sessions per job. **Sub-agents**: `src/agents/subagents/` — `spawn/`, `registry/` (`subagent-registry.types.ts::SubagentRunRecord`, `getLatestLiveSubagentRunByChildSessionKey`), `completion/session-followup-completion.ts`, `announce/`, and `swarm/` (`swarm-collector-capability.ts`: `bindCollectorSpawnTool`, `runWithJoinedCollectorSpawn` — collector agents that join results of fanned-out children). Gateway-side adoption: `gateway/agent-turn/agent-run-subagent.ts` ("Native subagent registration and paused-run adoption precede Gateway acceptance"). Multi-agent routing: `gateway/agent-list.ts::listGatewayAgentsBasic` + per-agent sessions, with cross-agent session access audited by `src/security/audit-extra.summary.ts::collectCrossAgentSessionAccessFindings`.

## 7. MEMORY & STATE

Sessions persist via `src/config/sessions/` (`combined-store-gateway.ts` bridging JSON + SQLite stores, `conversation-registry.ts`, `session-state-events*.ts` with a dedicated read worker, `cleanup-service.ts`, `session-diff*`, transcript watermarking `ambient-transcript-watermark.ts`) plus `src/sessions/` (lifecycle locks `session-lifecycle-locks.ts`, admission `session-lifecycle-admission.ts`, work admission, upstream links). Long-term memory: bootstrap files in the workspace — `src/agents/bootstrap-files.ts` (`DEFAULT_MEMORY_FILENAME` = MEMORY.md-style file, `DEFAULT_USER_FILENAME`, bootstrap-completion marker custom type `openclaw:bootstrap-context:full`, injection mode `resolveContextInjectionMode`), `src/memory/` (`root-memory-files.ts`, `memory-artifact-provenance.ts` tying memory writes to provenance). Durable system state is SQLite under `src/state/` (`openclaw-state-db.ts`, per-agent DBs, deletion journals `agent-deletion-journal*.ts`, provenance kernel `agent-provenance.kernel.ts`) — config, session rows, cron jobs, pairing, allowlists all survive restarts; restart recovery is explicit (`main-session-recovery-*`, `agent-restart-recovery-context.ts`, `service.restart-catchup`).

## 8. CROWN JEWELS

1. **Two-level lane queue (session ⊂ global)** — `run-orchestrator.ts::createEmbeddedRunLaneController` (`enqueueSession`/`enqueueGlobal`, deadlines, progress notes). Rust: `tokio::sync::Semaphore` global + per-session `mpsc` lanes with deadline watchdogs.
2. **Composable admission-currency assertions** — `composeSessionSourceAssertion([...])` in `agent-turn-service.ts`; each async phase carries a cheap closure that throws if superseded. Rust: `Arc<AtomicUsize>` epoch tokens per run, checked at phase boundaries.
3. **Idempotent turn replay** — `replayAgentTurnIfCached` + `createAgentDedupeLifecycle` keyed by `agentDedupeKeys`; duplicate messages (channel retries) return the cached acceptance. Rust: dedupe cache keyed on (session, sender, hash) with acceptance replay.
4. **Prepared-runtime leases with generation checks** — `acquireAgentRunPreparedModelRuntime` + `bindRunToPreparedModelRuntime`; a run pins config/plugins, and a replaced generation is detected mid-run. Rust: `arc-swap` generation snapshot + lease guard validating snapshot identity before each tool batch.
5. **Single-owner gateway lock with loss signal** — `acquireGatewayLock` + `captureGatewayStateOwner` abort (`server.ts`); losing the lock triggers graceful close, no split-brain. Rust: `flock`/`fs2` lock file whose loss is watched via a poll thread → `CancellationToken`.
6. **Respawn-to-health entry chain** — `entry.respawn.ts` / `entry.compile-cache.ts`: each layer fixes one runtime problem and re-execs; parents never run the CLI. Rust: re-exec via `Command` with env markers (`isNodeHostLauncherChild` equivalent).
7. **System-owned cron declarations for autonomy** — heartbeat as an undeletable cron job (`HEARTBEAT_TASK_DECLARATION_PREFIX`, `cron-tool-creator-cap`), giving proactive behavior with durable scheduling, catch-up, and delivery plans. Rust: scheduled tasks stored in SQLite with owner==system and an agent-facing API restricted to create/read.
8. **Provenance-tagged writes + exec safeBins** — `createMemoryWriteProvenanceObserver` (agent vs untrusted origin) and `safeBins`/`safeBinTrustedDirs` allowlists that skip interactive approval only for known-trusted binaries. Rust: write auditor keyed on turn taint + a `Command` allowlist layer in the exec tool.

## 9. WHAT NOT TO COPY

- **Channel product surface**: WhatsApp/Telegram/Discord transports, `progress-draft-compositor`, reactions/typing lifecycles, mention/DM gating — a terminal harness has one "channel" (the TTY); at most adopt the envelope/route split.
- **Device/daemon installers**: `src/daemon/` launchd/systemd/schtasks machinery, `appcast*.xml`, Docker/Fly/Render deploy files, node-host launcher — irrelevant to a single-binary Rust CLI.
- **Control UI / canvas / portals**: `ui/`, `src/canvas/`, `gateway/portals/`, desktop stream brokers, Tailscale exposure — web surface, not terminal.
- **Media generation pipelines**: `tts/`, `talk/`, `image-generation/`, `music-generation/`, `video-generation/`, `meeting-bot/`, `realtime-transcription/`.
- **Preauth/connection budgets, TLS, WS compression**: multi-client hardening; a local terminal harness needs none of the network auth stack (though `auth-rate-limit.ts`'s scheduler-injected clock is a nice testability pattern to keep).
- **Session sharing / webchat connectors** (`session-sharing.ts`, `operator-role-policy.ts`): multi-tenant concerns; keep the simpler single-owner model.
