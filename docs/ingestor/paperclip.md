# Paperclip (paperclipai/paperclip) — Source Dossier for McHarness

Canonical repo: https://github.com/paperclipai/paperclip (branch `master`) — "The open-source app everyone uses to manage agents at work." 103k stars. A company/workplace metaphor for multi-agent orchestration; drives Claude Code, Codex, Cursor, Gemini, Grok, Hermes, OpenClaw, Pi via adapters. Audit against shallow clone of `master`.

## REPO MAP
- **server/** — Node control plane (`server/src/services/` has ~400 service files; `server/src/adapters/`, `routes/`, `realtime/`, `secrets/`, `storage/`). The whole company brain lives here.
- **ui/** — React dashboard (Tailwind v4 tokens in `ui/src/index.css`; DESIGN.md is a UI-only spec).
- **cli/** — `paperclipai` npm CLI; agent-facing (`paperclipai agent local-cli`).
- **packages/** — `shared` (zod validators/types), `db` (Drizzle Postgres schema, ~170 tables under `packages/db/src/schema/`), `adapters/` (claude-local, codex-local, cursor-local/cloud, gemini-local, grok-local, hermes, hermes-gateway, kimi-local, openclaw-gateway, opencode-local, pi-local), **paperclip-runner** (the native runner protocol — Rust owns production under `runner/`), `plugins/`, `skills-catalog/`, `teams-catalog/`, `mcp-server/`, `paperclip-eval-kernel/`.
- **skills/** — agent skills incl. the 790-line `skills/paperclip/SKILL.md` (the agent operating manual), `paperclip-board/`, `paperclip-create-agent/`, `paperclip-converting-plans-to-tasks/`, `complain/`, `suggestion-box/`, `para-memory-files/`, `slack/`, `agentmail/`.
- **tools/agent-shim/** — a Go shim (`main.go`, `runtime_command.go`) wrapping external agent processes.
- **integrations/assistant-plugins/**, **evals/**, **adapter-plugin.md** (work log on external adapter phase 1), **DESIGN.md** (UI tokens), **rules/, maps/, doc/, docs/**.

## COMPANY MODEL
Core entities are Drizzle Postgres tables in `packages/db/src/schema/`:
- **`companies.ts` → `companies`**; membership via `company_memberships.ts`, roles via `instance_user_roles.ts`.
- **`agents.ts` → `agents`**: `companyId`, `role` (default "general"), `title`, `reportsTo` (self-FK — org chart), `capabilities`, `adapterType` (default `"process"`), `adapterConfig`/`runtimeConfig` (jsonb), `budgetMonthlyCents` + `spendMonthUtc` + `spentMonthlyCents` (per-agent budget on the row), `lifecycleState`/`lifecycleHolds`/`lifecycleVersion` (fenced lifecycle), `status`, `pauseReason`, `lastHeartbeatAt`, `permissions` (jsonb).
- **`issues.ts` → `issues`** (tasks; UI calls them "tasks", DB says "issues" — SKILL.md explicitly declares this duality): `assigneeAgentId` XOR `assigneeUserId`, `checkoutRunId` + `executionRunId` + `executionLockedAt` (atomic checkout), `parentId`, `goalId`, `projectId`, `reviewPolicy` (typed `IssueReviewPolicy`), `blockedByIssueIds`/`unblockDescriptor` (`IssueUnblockDescriptor`), `executionPolicy`/`executionState` jsonb (review stages + monitors), `monitorNextCheckAt`/`monitorAttemptCount` (durable watcher), privacy columns (`privacyRootIssueId`, `visibility open|private` with a DB `check`), `originKind` + partial unique indexes making "one active recovery incident per origin" DB-enforced.
- **`goals.ts` → `goals`**, `budget_policies.ts → budgetPolicies`, `agent_wakeup_requests.ts` (below), `heartbeat_runs.ts`, `routines.ts`, `approvals.ts`/`issue_approvals.ts`, `execution_workspaces.ts`, `project_workspaces.ts`, `documents.ts`/`document_revisions.ts`, `company_secrets.ts` + `company_secret_bindings.ts`.
The shared types (`packages/shared/src/`) are zod-first: e.g. `agentAdapterTypeSchema` in `adapter-type.ts` (open string, server registry is the truth), `AgentLifecycleState`, `IssueReviewPolicy`.

## AGENT RUNTIME & ORCHESTRATION
- **Heartbeat model** (README + SKILL.md): agents don't run continuously; a DB-backed wakeup queue wakes them. `packages/db/src/schema/agent_wakeup_requests.ts`: `status` default `"queued"`, `coalescedCount`, `idempotencyKey`, `source`, `claimedAt`/`finishedAt`, and ~8 partial unique indexes acting as per-flow idempotency fences (`'issue_review_path_lost:%'`, `'question-response:%'`, `'tool-action-response:%'`…). Coalescing = multiple wake reasons collapse into one run.
- **Native runner**: `packages/paperclip-runner/` — "Rust owns the production runner under `runner/`" (a **rust-toolchain.toml** sits there). TS provides PRP v1 (Paperclip Runner Protocol) validation/replay, durable WebSocket delivery/recovery, and a conformance oracle. Drivers: Codex, OpenCode, ACPX (Claude/Codex/Grok/Cursor ACP profiles), Claude Managed, AWS AgentCore. `acpx-profiles.json` pins versions/command digests; `cursor-contract.json`/`cursor-distributions.json` pin Cursor closures by sha256.
- **Session continuity**: continuation with `toolRefreshOnResume` capability; deterministic "handoff" when recovery needs a fresh conversation — bounded 24,000-byte history loader with explicit truncation markers; compact continuation messages re-remind the model to obtain an accepted `paperclip_finish`/`paperclip_block` result ("reports from earlier turns do not finish the new turn").
- **Adapters (legacy)**: `server/src/adapters/registry.ts` with `registerServerAdapter`/`requireServerAdapter` (adapter-plugin.md); per-adapter dirs under `packages/adapters/`; `tools/agent-shim/main.go` (Go) shims external processes. Run-scoped auth: short-lived run JWTs (`server/src/agent-auth-jwt.ts`), `X-Paperclip-Run-Id` header links every mutation to the run.

## GOVERNANCE
- **Budgets**: `budget_policies.ts` — `scopeType`/`scopeId` (company/agent/project/goal scoping), `metric` (`billed_cents`), `windowKind`, `warnPercent` (default 80), `hardStopEnabled`, `reservationCents` (reserved spend so in-flight work doesn't blow past), `unpricedUsagePolicy: "block"`, and `enforcementVersion` vs `enforcementDeliveredVersion` — budget changes are versioned until delivered to the runner. Plus per-agent `budgetMonthlyCents` on `agents` and `budget_incidents.ts`.
- **Approvals**: `approvals.ts`, `issue_approvals.ts`, `approval_comments.ts`; execution-policy review stages on `issues.executionState` (`currentStageType`, `currentParticipant`, `returnAssignee` — approve = PATCH to `done`, changes = PATCH to `in_progress`, auto-reassignment between stages).
- **The disposition guard**: SKILL.md documents `invalid_issue_disposition` — the server rejects an agent's move to `in_review`/`done` unless a *real* wake path exists (typed participant, approval, pending interaction with a `questionSet`, or a scheduled monitor with non-null `monitorNextCheckAt`). "Narration is not a wake path." Also `in_review_without_action_path` recovery classifier.
- **Human-in-the-loop**: `issue_thread_interactions.ts` — typed question payloads `ask_user_questions` with `resolverPolicy: human_only|anyone`, `continuationPolicy: wake_assignee`, idempotency keys; block/permission denials render as durable error cards. `decision_queues.ts`, `issue_watchdogs.ts`, `issue_tree_holds.ts` (pause whole subtrees), `agent-instruction-authorization.ts`, `company_secret_proposals.ts` (secrets require proposal/approval), `tool_access.ts` + gateway actions Allowed/Ask-first/Off.

## ADAPTERS & PLUGINS
`adapter-plugin.md` documents phase-1 of open adapters: server registry became mutable (`registerServerAdapter`/`unregisterServerAdapter`/`requireServerAdapter` in `server/src/adapters/registry.ts`), input validation opened to any non-empty string via `agentAdapterTypeSchema` (`packages/shared/src/adapter-type.ts`) while **server-side `assertKnownAdapterType` in `server/src/routes/agents.ts` is the real gate**; mirrored mutable UI registry (`ui/src/adapters/registry.ts`). Plugin infra: `packages/plugins/`, `server/src/services/adapter-plugin-store.ts`, DB tables `plugins.ts`, `plugin_config.ts`, `plugin_jobs.ts`, `plugin_webhooks.ts`, `plugin_managed_resources.ts`, `plugin_lifecycle_acknowledgments.ts`. External runtimes plug in three ways: process adapters, HTTP/webhook bots ("if it can receive a heartbeat, it's hired"), and external adapter packages.

## SERVER & API
Postgres (Drizzle, `packages/db/drizzle.config.ts`) with **embedded Postgres** option (`embedded-postgres-supervisor.ts`, `embedded-postgres-owner.ts`) — zero-config local install. Heavy migration-safety tooling (`check-migration-safety.ts`, snapshot-drift tests).
API: REST under `/api` (routes in `server/src/routes/`), bearer auth: human sessions or agent short-lived run JWTs (`agent-auth-jwt.ts`); `X-Paperclip-Run-Id` audit header on every mutation.
Realtime: `server/src/realtime/live-events-ws.ts` (UI event stream), `runner-prp-ws.ts` + `runner-prp-outbound.ts` (durable runner WebSocket with replay), per-domain WS (`environment-custom-image-terminal-ws.ts`). Also `tool_action_deliveries.ts`/`connection_event_deliveries.ts` for async delivery with idempotency.
CLI and UI are both thin clients over the same REST+WS; agents themselves use the same API (skills/paperclip SKILL.md is essentially API docs as a skill).

## SKILLS & TOOLS
**Skills are Claude-SKILL.md-compatible**: `skills/paperclip/SKILL.md` has YAML frontmatter (`name`, `description`) exactly like Anthropic skills, with `references/` and `scripts/` (e.g. `scripts/paperclip-issue-update.sh` — verifies HTTP status, retries connection failures). Company skill governance: `company_skills.ts`, `company_skill_policies.ts`, `company_skill_sources.ts`; versioning/restore via `agent-instruction-revisions.ts` and document revisions. A skill catalog ships in `packages/skills-catalog/`.
The paperclip skill is *how the agent learns the platform*: identity → inbox → pick work → checkout → context → work → status → delegate, with hard rules (never retry a 409 checkout; verify writes — an empty response body means the write FAILED; bounded write retry: after 2 consecutive failures stop retrying for the heartbeat).
`tools/agent-shim/main.go`: minimal Go process wrapper for arbitrary agent CLIs.

## CROWN JEWELS
1. **DB-backed wakeup queue with coalescing + idempotency fences** (`agent_wakeup_requests.ts`: `coalescedCount`, partial unique indexes on `idempotencyKey` prefixes). Why: durable, crash-safe job queue where "same reason twice" collapses and each flow class has its own fence. *Rust:* `wakeup_requests` table or in-process `HashSet<(kind, key)>` behind a Postgres-backed `tokio` worker.
2. **Atomic task checkout** (`issues.checkoutRunId`/`executionRunId`/`executionLockedAt`; 409 on conflict, "never retry a 409"). *Rust:* single `UPDATE ... WHERE execution_run_id IS NULL` returning row-count; on 0, skip.
3. **Typed waiting postures instead of polling** (`in_review` + pending interaction, `blocked` + `blockedByIssueIds`, monitors as durable state `monitorNextCheckAt`). Why: the *server* enforces that every parked task has a live wake path — no orphaned "waiting" states. *Rust:* enum `Wait { Reviewer, Interaction(QuestionSet), Blockers(Vec<TaskId>), Monitor{next_check} }` + guard that `Wait` implies a scheduled waker.
4. **Disposition guard / "narration is not a wake path"** (`invalid_issue_disposition`). Why: kills the #1 LLM failure mode — claiming a watcher/reviewer exists. *Rust:* validate state transitions against existential facts, not message text.
5. **Bounded deterministic handoff on session loss** (paperclip-runner README: 24,000-byte ceiling, truncation markers, secret redaction before model submission). *Rust:* `HandoffBuilder` with byte budget + marker insertion.
6. **Budget enforcement with reservations and versioned delivery** (`budget_policies.reservationCents`, `enforcementVersion`/`enforcementDeliveredVersion`). Why: in-flight spend is reserved so hard-stops are accurate; policy changes must be acked before enforced. *Rust:* `BudgetLedger` with `reserve()/commit()` and monotonic version the runner must ack.
7. **Run-scoped JWT + mandatory run-attribution header** (`agent-auth-jwt.ts`, `X-Paperclip-Run-Id`). Why: every mutation is auditable to a run; credentials expire with the run. *Rust:* short-lived signed token embedding `run_id`; middleware rejects mutations without it.
8. **Skill-as-operating-manual + write verification discipline** (`skills/paperclip/SKILL.md`: "an empty response body means the write FAILED", bounded write retry). *Rust:* embed the harness contract as a generated prompt/system skill; pair every write helper with response-body verification and a 2-strike circuit breaker.

## WHAT NOT TO COPY
- **~170-table Postgres schema + embedded Postgres + migration-safety machinery** — massively over-engineered for a terminal harness; use SQLite/JSONL.
- **Rust/TS dual runner with PRP conformance kits, ACPX profile digests, Cursor sha256 contracts, provider-pack attestation** (`paperclip-runner/README.md`) — supply-chain theater for a 103k-star product; a trait + subprocess spawn suffices.
- **Company/organization isolation in every table + index** (`companyIdUq` composites, partial indexes per `originKind`) — multi-tenant pattern irrelevant to a local harness.
- **UI design-token governance** (DESIGN.md) — pure web concern.
- **Chat connectors** (Slack/Discord/Telegram/AgentMail/voice tables in `packages/db/src/schema/`) — huge surface, low harness value.
- **Secret-proposal workflows and permission gates as DB rows** — right for a shared server; a TUI can use OS keychain + explicit per-run confirmation.
