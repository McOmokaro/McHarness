# open-design (OpenDesign) — Source-Level Dossier

Repo: `nexu-io/open-design` — TypeScript, pnpm workspace, ~102k★, "The 1st Collaborative AI Design Agent Workspace. Local-first and open source" (topics: agent-skills, dsh, claude-design, hermes-agent). Audited from shallow clone of `main`.

Verification level: direct reads of daemon loop/resume/skill/storage/guard sources; product-surface claims from README + file listings.

## 1. REPO MAP

pnpm workspace (`pnpm-workspace.yaml`), Node ~24. Two primary trees:

- **`apps/`** — `daemon/` (the agent core, HTTP server + child-process orchestrator), `desktop/` (Electron shell), `web/` (SPA), `closure/`, `packaged/`.
- **`packages/`** — `dsh-runtime/` (DeepSeek Harness profile plugin: `src/{index,protocol,startup,invariant}.ts`), `contracts/` (shared types), `platform/`, `sidecar/`, `plugin-runtime/`, `agui-adapter/`, `host/`, `metatool/`, etc.
- Content planes at root: `skills/` (~160 SKILL.md packages), `design-systems/` (151 brand packages: `DESIGN.md` + `manifest.json` + `tokens.css`), `design-templates/`, `prompt-templates/`, `plugins/`.

**Agent core**: `apps/daemon/src/`. Entry: `server.ts` (resolves `OD_DATA_DIR` → `RUNTIME_DATA_DIR`, registers routes; ~5k+ lines), `cli.ts`. Key subsystems: `runtimes/` (process launch + stream parsing + run lifecycle), `prompts/` (`system.ts` = 2,239-line prompt composer), `skills.ts` (skill registry), `storage/`, `design/`, `collab/` (~60 files), `artifacts/`, `db.ts` (SQLite schema, 5,493 lines).

**Critical framing**: OpenDesign ships **no LLM loop of its own**. It spawns coding-agent CLIs (`claude`, `codex`, `dsh`, `hermes`, …) as child processes and re-parents their streams. The "agent loop" here is *run lifecycle management over external loops* — exactly the layer a Rust harness must own.

## 2. AGENT LOOP & SESSION

**Runtime adapters.** Each CLI is a declarative `RuntimeAgentDef` in `apps/daemon/src/runtimes/defs/*.ts` (28 files: `claude.ts`, `codex.ts`, `deepseek-harness.ts`, `hermes.ts`, …). `deepSeekHarnessAgentDef` (`defs/deepseek-harness.ts:50`) shows the full shape: `bin: 'dsh'`, `versionArgs`, `versionPolicy {supportedVersions, supportedVersionPattern, parse}`, `compatibilityProbe` (`--profile open-design --probe` with `preflight: hasOpenDesignProfile`), `listModels`, `buildArgs: () => ['--profile','open-design','--stdio']`, `promptViaStdin: true`, `streamFormat: 'dsh-profile-jsonl'`, `resumesSessionViaProfileStdio: true`, `capturesSessionIdFromStream: true`. Launch resolution is `runtimes/launch.ts` (`resolveAgentLaunch`, `applyAgentLaunchEnv`) with per-CLI binary discovery (`codexNativeCandidates`). Stream parsing is per-format handlers: `runtimes/claude-stream.ts`, `json-event-stream.ts`, `plain-stream.ts`, `qoder-stream.ts`, `copilot-stream.ts`.

**Runs.** `runtimes/runs.ts` (2,654 lines) owns run state: `TERMINAL_RUN_STATUSES = {succeeded, failed, canceled}`, `RUN_STATE_SCHEMA_VERSION`, and `runHasHostRecordedDeliveryFailure` (line 70) — a completeness verdict that accepts **only host-recorded evidence** (media failures the daemon itself logged), never the model's own prose. Analytics summaries (`summarizeToolEvents`, `summarizeModelStepEvents`) fold the event stream into per-call timing/usage. Lifecycle helpers in `runtimes/chat-run-lifecycle.ts`: `resolveChatRunInactivityTimeoutMs`, `classifyChatRunCloseStatus`, `agentStdinPromptPayload`.

**Session resume** — the deepest piece, `apps/daemon/src/agent-session-resume.ts`:
- `evaluateResumeInvalidation` (line 191) rejects a stored upstream session on `model_changed`, `cwd_changed`, `missing_cursor`, `conversation_advanced` (cursor = the session's own last assistant message id; it must still be the latest completed assistant turn).
- `resolveAgentResumeContext` (line 214) returns `{storedSessionId, resumeSessionId, newSessionId, isResuming, storedStablePromptHash, storedInputTokens, invalidationReason}` from the `agent_sessions` SQLite row (PK `(conversation_id, agent_id)`; columns `stable_prompt_hash`, `stable_prompt_sections`, `model`, `cwd`, `last_message_id`, `last_input_tokens` — `db.ts:210`).
- `resolveAgentResumePromptPolicy` (line 121) **couples** native resume and transcript skipping: if the guard rejects, the daemon must recompose the full transcript (`mode: 'full-transcript'`, `requiresFullTranscript: true`). `resolveAgentResumeFailurePolicy` (line 152) auto-clears a stale handle and reseeds only when a resume was actually attempted. `resolveResumeContinuationSeed` (line 284) handles a subtle divergent case: a "continue the run" directive landing in a fresh session that never heard the original request — the daemon reseeds the request from persisted history.
- Crash recovery: `runtimes/run-restart-recovery.ts` (`interruptDurableRunAfterDaemonRestart`, `RESTART_ERROR_CODE`) marks durable runs interrupted after daemon restart.

**Loop safety**: `tool-loop-guard.ts` (see §8) plus `amr-stderr-filter.ts`, `role-marker-guard.ts`.

## 3. DESIGN-GENERATION PIPELINE

A brief becomes an artifact in host-controlled stages:

1. **Prompt composition** — `apps/daemon/src/prompts/system.ts`, `composeSystemPrompt` (line 900). A single fork point branches to `composeOdNextStrategyRequestPromptV2` (OD Next runs), else the classic/slim stack. Ordering is **prompt-cache aware**: static charter first (`renderSlimCoreCharter`), then conversation-stable overrides (`CHAT_MODE_OVERRIDE`, `PLAN_MODE_OVERRIDE`, `API_MODE_OVERRIDE` for plain-stream/BYOK), then project-stable context (design-system body, tokens.css, components manifest, direction library — gated: if a design system is active, the 6.7KB direction catalogue is *replaced* by a slim index the agent dereferences via `od tools directions --id`), and turn-variable blocks pushed last so a mid-conversation signal flip invalidates only the cached suffix.
2. **Routing** — `strategies/od-next/rollout.ts`: `evaluateOdNextRollout` / `stableOdNextAssignmentBucket` (sha256 `salt:identity` → bucket % 10,000) decide `off|observe|active` with a three-state config contract ("a file that exists but cannot be believed resolves to `off`", line 87).
3. **Execution** — the spawned CLI writes single-page HTML artifacts into a daemon-managed project dir; OD injects `DESIGN.md` as the brand contract. BYOK/plain runs without filesystem tools instead return one complete `<artifact>` block (README line 294).
4. **Host-side finalization** — `artifacts/deliverable-syntax-*.ts`: a *bounded* repair loop (`DEFAULT_DELIVERABLE_SYNTAX_REPAIR_MAX_ATTEMPTS = 3` in `deliverable-syntax-repair.ts:7`; `HOST_SYNTAX_MAX_PATCHES = 8`, `HOST_SYNTAX_MAX_EDITED_CHARACTERS = 32`, `HOST_SYNTAX_REPAIR_BUDGET_MS = 1000` in `deliverable-syntax-finalization.ts:28-30`). `decideDeliverableSyntaxRepair` + `renderDeliverableSyntaxRepairPrompt` emit an XML-tagged repair request; `deliverable-syntax-safe-fix.ts` (`proposeDeliverableSyntaxSafeFix` / `commitDeliverableSyntaxSafeFix`) applies char-limited patches without the model.
5. **Versioning** — `run-html-version-snapshots.ts`: `snapshotAiHtmlVersionsForRun` diffs the run's `touchedPaths`, filters `.html?`, and calls `ensureCurrentProjectFileVersion(..., {source:'ai', prompt, origin})`. `project-file-versions.ts` provides `withProjectFileVersionLock`, `projectFileVersionContentDigest`, `listProjectFileVersions` — a manifest + content-digest version model with a lock context.
6. **Produced-files invariant** — `runtimes/run-produced-files.ts`: the daemon fills `messages.produced_files_json` from its own filesystem diff at run end ("A FLOOR, NOT A VERDICT" — idempotent, client writes win). This fixed a real bug where the association lived only in a browser SSE handler.
7. **Synthesis/handoff** — `design/finalize-design.ts` (`buildSynthesisPrompt`, `truncateTranscriptForPrompt` with a lossless head/tail split and `{"kind":"truncated","omittedBytes":N}` sentinel, `callFinalizeProviderWithRetry`); `design/handoff-design.ts` (`HANDOFF_SYSTEM_PROMPT`, `synthesizeHandoffPrompt`) summarizes an in-flight session so a fresh agent can continue it.

## 4. SKILL SYSTEM

Confirmed SKILL.md-style. **Registry**: `apps/daemon/src/skills.ts` — scans ordered roots for `<dir>/SKILL.md`, parses frontmatter via `design-systems/frontmatter.ts` (`parseFrontmatter`), **first root wins on id collisions** so user skills shadow built-ins without erasing them (`listSkills`, line 232; `source: 'user' | 'built-in'`). Renames are bridged by `SKILL_ID_ALIASES` (line 28: `"taste-skill" → "design-taste-frontend"`) resolved via `findSkillById` — a rename-forgetting else silently drops the skill body from prompt composition. Rich `od.*` frontmatter extensions: `mode` (`utility|image|video|audio|deck|design-system|template|prototype`), `surface`, `platform`, `scenario`, `category`, `preview`, `craft`, `design_system.requires/generates`, `inputs/outputs`, `capabilities_required` (e.g. `file_write`), and a per-skill **Critique Theater policy** (`od.critique.policy: required|opt-out|opt-in|null`) that overrides project/env/phase tiers in the rollout resolver. Workspace scoping: `skillVisibleFromWorkspace` (line 182) checks `workspace_resources` bindings — built-ins are global; team skills visible to team members; personal skills require the creator; tombstoned team mirrors are hidden while the on-disk copy survives. **Invocation**: skill bodies are *composed into the system prompt* (`composeSystemPrompt({skillBody, skillName, skillMode, skillModes…})`), not executed. Example skill: `skills/design-brief/SKILL.md` — trigger keywords, I-Lang structured brief format (`[PLAN:@DESIGN|type=saas_landing]`), closed-vocabulary token resolution tables, mood-conditional default rules, a mandated DESIGN.md outline, and a required "report unspecified dimensions" transparency section. No inheritance between skills — composition only.

## 5. TOOLS & SECURITY

OD owns no internal tool registry; tools belong to the spawned CLIs. What OD controls:

- **Run-scoped MCP bundles** — `run-tool-bundle.ts`: `RunToolBundle {mcpServers}`, `sanitizeMcpConfig`, `validateRunToolBundleForAgent` dispatching on the def's `externalMcpInjection` mode (`claude-mcp-json` → project `.mcp.json`, requires managed project; `opencode-env-content`/`mimo-env-content` → env; `acp-merge` → stdio-only). `resolveExternalMcpServersForRun` **drops persisted MCP servers entirely in sandbox mode**.
- **Exec approvals** — inverted from a TUI harness: headless daemon runs pass bypass flags because "Daemon-managed headless runs have no interactive approval channel" (`defs/antigravity.ts:256`; `claude.ts:121` `--permission-mode bypassPermissions`; `amp.ts` `--dangerously-allow-all`). Codex gets special sandbox handling (`codexNeedsDangerFullAccessSandbox`, workspace-write fallbacks on Windows, `defs/codex.ts:252-328`).
- **Sandboxing** — `sandbox-mode.ts`: `OD_SANDBOX_MODE` + `resolveSandboxRuntimeConfig` builds a full jail root set (`agentHomeDir`, `cacheDir`, `configDir`, `tempDir`, `toolConfigDir`…); `applySandboxRuntimeEnv` redirects `HOME`, `USERPROFILE`, `XDG_*`, `TMPDIR/TEMP/TMP`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `NPM_CONFIG_USERCONFIG` into the jail. Import allowlist `OD_SANDBOX_IMPORT_ALLOWED_ROOTS` uses `fs.realpathSync.native` canonicalization + `isPathInsideDir` containment.
- **Edge hardening** — BYOK proxy (`routes/chat.ts`) runs `validateUserProviderBaseUrl` (resolved-IP SSRF check blocking internal/link-local/CGNAT) on every proxy/stream route; per-request `role-marker-guard.ts`; `origin-validation.ts`, `api-token-auth.ts`; `tool-input-path-scanner.ts` scans tool inputs for paths.
- **Guard rails** — `tool-loop-guard.ts` (§8) and host-evidenced failure verdicts (`runs.ts:70`).

## 6. LOCAL-FIRST PERSISTENCE

Two layers, both local by default:

- **SQLite** (better-sqlite3) — `apps/daemon/src/db.ts` schema (line 101+): `projects`, `workspace_projects`, `team_project_materializations`, `workspace_resources` (generic team-share bindings with `visibility` + `resourceState` tombstones), `templates`, `conversations`, `agent_sessions`, `messages` (with `events_json`, `produced_files_json`, `run_status`, `forked_into_json`), `message_event_batches` (small immutable stream batches folded into `messages.events_json` once at the terminal boundary, line 268), `daemon_maintenance_passes` (one-time data migrations recorded so they never re-scan), `preview_comments`, `tabs`, `deployments`, `routines`/`routine_runs`/`routine_schedule_claims`. Migrations are pragma-checked `ALTER TABLE` adds. Data root: `OD_DATA_DIR` → `RUNTIME_DATA_DIR` resolved in `server.ts`; `daemon-paths.ts` `resolveDataDir` falls back to `<projectRoot>/.od`. `AGENTS.md` §"Daemon data directory contract" is the enforced single source of truth for these paths (other docs must not restate them).
- **Project files** — `storage/project-storage.ts`: `ProjectStorage` interface (read/write/list/delete/stat with `StorageError{NOT_FOUND|TRAVERSAL|IO}`); `LocalProjectStorage` over `<dataDir>/.od/projects/` with strict traversal guards (`resolvePath` rejects `..`, NUL, backslash); `S3ProjectStorage` with **inline AWS SigV4 via `node:crypto`** (`aws-sigv4.ts`), pluggable `fetchFn`, page-capped LIST (1000), selected by `OD_PROJECT_STORAGE=s3`. **Versioning** — content-digest + manifest per file (`project-file-versions.ts`) with per-file locks; snapshots keyed to runs (`source: 'ai'`, prompt, `ArtifactOrigin`). Survives restarts: the DB, project files, version manifests; durable runs are *marked interrupted* rather than resurrected (`run-restart-recovery.ts`).

## 7. COLLABORATION LAYER

`apps/daemon/src/collab/` (~60 modules) — a hub-mediated team sync, not P2P CRDTs. Team shares materialize as **read-only mirrors**: `team-mirror-materializer.ts`, `team-mirror-promotion.ts`, `team-resource-state.ts`, tombstones via `resourceState: 'deleted'` bindings. Invites (`invite-create.ts`, `invite-continue.ts`), presence (`presence-tracker.ts`), publish scheduling (`publish-scheduler.ts`, `should-publish.ts`), hub subscriptions (`hub-events-subscriber.ts`, workspace-scoped SSE invalidation). Notable: **`collab/sync-digest.ts`** — a cheap change probe returning four *opaque* tokens (`max(updated_at)::text || ':' || count(*)`); the `count(*)` term makes hard deletes move the token, so ordering is meaningless and `===` is the only legal operation; readings are keyed `(accountId, workspaceId)` so a cross-account snapshot key is "unrepresentable"; in-flight coalescing, 2s timeout, 60s failure cooldown. Element-anchored review comments persist in `preview_comments` (db.ts:291) with `anchored_version` and `last_good_position_json`.

## 8. CROWN JEWELS

1. **Declarative runtime adapter defs** — `runtimes/defs/deepseek-harness.ts` (`deepSeekHarnessAgentDef`), `runtimes/types.ts` `RuntimeAgentDef`. 28 CLIs supported by one object literal each: bin, version regex policy, capability probe, model parsing, arg building, stream format, resume flags. *Why*: adapter complexity is data, not code. *Rust*: `trait RuntimeAdapter` + a `RuntimeDef` struct with `StreamFormat` enum; registry as a static table.
2. **Resume-invalidation guard** — `agent-session-resume.ts` `evaluateResumeInvalidation` + `resolveAgentResumePromptPolicy`. Native resume and transcript-skip are *provably coupled*; cursor = last assistant message id; any drift (`model_changed|cwd_changed|conversation_advanced`) forces full reseed. *Rust*: `ResumeGuard` over a persisted `AgentSessionRecord` with an `InvalidationReason` enum driving `Continue|Reseed`.
3. **Tool-loop guard with progress semantics** — `tool-loop-guard.ts` `createToolLoopGuard`: full-fidelity signature dedup (`computeToolSignature`, deliberately uncapped) vs truncated display; `isProgressSuccess` distinguishes mutating success (clears tallies) from read-only success (must not, else "fail→read→fail" fixation loops never trip); warn/halt modes via `OD_TOOL_LOOP_GUARD`. *Rust*: `ToolLoopGuard { consecutive: u32, tallies: HashMap<String, u32> }` with capped maps.
4. **Host-evidenced turn completion** — `runs.ts:70` `runHasHostRecordedDeliveryFailure`: completeness judged only on failures the host observed, never model self-report; scoped per attempt. *Rust*: a `SideEffectLedger` per run consulted at finalize.
5. **Cache-ordered prompt composer** — `prompts/system.ts` `composeSystemPrompt`: sections sorted by stability (static charter → conversation-stable → project-stable → turn-variable last), with explicit fork points and per-runtime plan-tool notes. *Rust*: `Vec<PromptSection>` with a `Stability` class and byte-stable rendering.
6. **Run-diff file versioning** — `run-html-version-snapshots.ts` `snapshotAiHtmlVersionsForRun` + `project-file-versions.ts` (`withProjectFileVersionLock`, `projectFileVersionContentDigest`): every AI-touched file gets a content-addressed version bound to run, prompt, and origin. *Rust*: `VersionStore` keyed `(project, relpath)` → digest-chained entries behind a file lock.
7. **Sandbox env redirection** — `sandbox-mode.ts` `applySandboxRuntimeEnv` + `SandboxRuntimeConfig`: jail via environment remapping (HOME/XDG/TMP/tool homes) plus realpath-canonicalized allowlists — cheap, cross-platform, no OS namespaces. *Rust*: `SandboxConfig` producing `Command::env`s + `PathBuf` containment checks.
8. **Opaque sync-digest tokens** — `collab/sync-digest.ts`: comparison-only change probes where the count term makes deletes visible and ordering meaningless, with identity-keyed snapshots. *Rust*: `SyncDigestReader` with coalescing + cooldown for any remote state probe.

## 9. WHAT NOT TO COPY

- **The GUI surface**: `apps/desktop` (Electron), `apps/web` (SPA), `packages/components`, preview iframe servers, live-artifact reload machinery — McHarness renders in a TTY.
- **Media generation plane**: `media/`, `media-adapters/`, the 20+ `fal-*`/`venice-*` skills, HyperFrames/MP4 export, `prompt-templates/` (93 image prompts). Pure product.
- **The 26-CLI adapter menagerie**: port the *def pattern*, not the individual parsers (`codex-pets.ts`, `qoder-stream.ts`, etc.).
- **Cloud collab**: `collab/`'s Vela hub client, billing caches, invites, publish schedulers — local session sharing at most, not a control-plane client.
- **Telemetry/observability**: `langfuse-bridge.ts`, `observability/` delivery-state machines, `analytics.ts`, consent-gated replay.
- **Exporters**: `pdf-export.ts`, `deck-export.ts`, `transcript-export.ts`.
- **Plugin/MCP-install product features**: `mcp-agent-install.ts`, `plugins/`, `mcp-oauth.ts` — product distribution, not harness core.
- **The bypass-permissions exec posture** (§5) is *opposite* to a terminal harness's needs — McHarness should keep an approval channel and treat OD's sandbox-env redirection as the compatible piece to adopt.

**Explicitly absent (verified)**: no self-hosted model loop, no CRDT/OT engine, no vector DB, no skill *inheritance* (composition only), no tool-permission UI — OD deliberately outsources all of these.
